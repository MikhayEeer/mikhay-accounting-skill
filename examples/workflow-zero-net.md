# 零金额与净额：一件事一条记录

用户说：「机票 500，公司报销 500」，「多报了 20」，「和朋友 AA，我只花了 50」，「猫粮全额退款」。这些都是同一件事，不要写成两条。

## 1. 全额报销 / 全额退款 / AA 后净额为 0

原来的一条：

```json
{"id": "flight", "时间": "2026-06-01 10:00", "收支类型": "支出", "金额": -500, "类别": "出行交通", "子类": "飞机", "账户": "招商银行", "备注": "机票", "报销状态": "待报销"}
```

到账后直接改成：

```json
{"id": "flight", "时间": "2026-06-01 10:00", "收支类型": "支出", "金额": 0, "类别": "出行交通", "子类": "飞机", "账户": "招商银行", "备注": "机票，已全额报销", "报销状态": "已报销"}
```

`金额=0` 是合法记录。不要新增一条 `+500` 的 `报销` 或 `收入`。

## 2. 部分退款 / 部分 AA

午饭 35，朋友转回 10：把原记录改成 `-25`。

机票 500，公司只报 300：把原记录改成 `-200`，`报销状态` 写 `已报销`。

## 3. 多报了

机票 500，报销 520：

```json
{"id": "flight", "时间": "2026-06-01 10:00", "收支类型": "收入", "金额": 20, "类别": "收入", "子类": "补贴", "账户": "招商银行", "备注": "机票报销多出 20"}
```

这条从 `支出` 改成 `收入`，金额为差额，仍然是一件事一条记录。

## 4. 校验与汇总

```bash
python scripts/validate_ledger.py data/ledger/2026/2026-06.json
python scripts/summarize_ledger.py data/ledger/2026/2026-06.json
```

- `0` 不会报错。
- 汇总的 `支出` 是净支出；上面第 1 条不计入花销。
- 需要保留原始金额时（例如发票对账），才另写 `收支类型=报销` 行并加 `reimburse_of`；这是兼容路径，不是默认写法。
